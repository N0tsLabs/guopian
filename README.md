出去玩拍了几千张照片，回来面对的是一个几天不想打开的文件夹。

过片把这件事变成一次快速的心流：照片一张张以卡片形式推到你面前，<kbd>←</kbd> 扔掉、
<kbd>→</kbd> 留下，软件在背后把每张照片的**具体问题**逐条列出来。

![卡片视图](docs/img/card.png)

画面正下方那一条就是它的重点：不是"这张 62 分"，而是**「白平衡色偏 85%」** ——
一个你不知道就看不出来的具体问题。左侧是全部照片，点一行就跳过去。

> **全程本地处理，不联网，不上传任何照片。**
> **「不过」不是删除** —— 它只是你对这张照片的判断，筛选全程一个字节都不动原图；
> 之后确认执行，也只是移动到隔离文件夹，随时一键回滚。

## 这是什么

一个**本机的、键盘驱动的照片筛选工具**。它不修图、不管理图库、不做后期 ——
它只做一件事：**帮你以最快的速度过完一批照片，并且告诉你每张哪里不对。**

它不联网。没有账号。不上传。分析在你自己的 CPU 上跑。

---

## 它解决什么问题

挑照片很慢，而且慢在两个地方：

1. **看不过来。** 一次旅行几千张，其中大部分是同一场景的连拍，只有一两张是好的。
2. **说不清为什么。** 你知道这张不对劲，但要盯着看两秒才反应过来是"眼睛闭了"还是"没对上焦"。

过片把这两件事一起解决：**用键盘把翻页速度拉满，同时在画面上直接标出问题所在。**

---

## 凭什么不一样

大多数同类工具给你一个**综合质量分 + 一个阈值**。这条路走不通 ——
一个绝对分数跨相机、跨场景、跨题材根本不可比：雪山天生就亮会被判过曝，
大光圈人像的背景天生就糊会被判模糊。

过片换了一条路：

| | 传统做法 | 过片 |
|---|---|---|
| **判定** | 综合分 + 全局阈值 | **逐条问题清单 + 组内相对排名** |
| **模糊** | 写死一个数 | **按相机机型自动标定**，且必须同时低于本次会话中位数的一定比例 |
| **曝光** | 绝对占比 | **绝对下限 + 本次会话分位数**双条件 —— 黄昏拍的整批不会被全判为"太暗" |
| **相似照片** | 各自独立评分 | **只在同一次拍摄内部比较**（同相机、同镜头、同光线，干扰变量自动抵消） |
| **"看别处"** | 当作缺陷 | **抓拍时看别处是常态，不是缺陷**：会话相对 + 只作提示，从不驱动「不过」 |
| **决策** | 保留 / 删除 | **过 / 不过 / 精选** —— 三个都是对照片的判断，没有一个是文件操作 |
| **执行** | 直接移动或删除 | **决策与执行分离**，二次确认 + 一键回滚 |

**最重要的一条：它给的不是一个分数，是一句话。**
不是"这张 62 分"，而是"右眼闭合 91%"、"高光溢出 12%"、"这一组里排第 8"。

## 它检查哪些问题

一共 **23 项**，每一项都告诉你**具体是什么**，而不是扣了多少分。

### 人脸（12 项）

| | |
|---|---|
| 眼睛闭合 / 眼睛可能闭着 | 嘴巴张开（可能在说话） |
| 眉头压低 | 视线没看镜头 |
| 头部偏转较大 | 人脸区域不够清晰 |
| 人脸高光溢出 | 人脸过暗 |
| 人脸太小 | 人脸贴近画面边缘 |
| 眼睛缺少眼神光 | |

### 全局（8 项）

| | |
|---|---|
| 高光溢出 | 暗部死黑 |
| 画面发灰、对比度低 | 模糊 / 失焦 |
| 噪点偏高 | 画面倾斜 |
| 分辨率偏低 | 压缩痕迹明显 |

### 相对判断（3 项）

| | |
|---|---|
| 与另一张几乎完全相同 | 相似组内排名靠后 |
| 白平衡色偏 | |

> 每一项的可信度不一样，`docs/design.md` 里有一节专门记录**哪些判断目前还不可靠、为什么**。

去 [Releases](https://github.com/N0ts/guopian/releases) 下载对应平台的压缩包，解压即用，不需要安装。

| 平台 | 文件 |
|---|---|
| Windows | `Guopian-x.y.z-windows-x64.zip` |
| macOS | `Guopian-x.y.z-macos-*.zip` |
| Linux | `Guopian-x.y.z-linux-x64.zip` |

**第一次启动会慢一点**（要解压人脸模型），之后就正常了。

### 关于那个窗口

启动后会打开一个**没有地址栏、没有标签页的窗口**。这不是 Electron ——
后端是一个只监听 `127.0.0.1` 的本地服务，前端是普通的网页，用系统的 Chromium 内核以
`--app` 模式显示。

这样做的原因很简单：**照片在你的硬盘上，处理在你的 CPU 上，中间没有任何东西需要联网。**
用浏览器内核是因为它已经装在你机器上了，而且 DevTools 直接可用（<kbd>F12</kbd>）。

## 怎么用

打开软件，先看到的是**打开过的项目**：

![首页](docs/img/home.png)

左边是项目列表，右边是选中项目的封面、路径、张数、器材、拍摄时间。
单击选中，双击才打开 —— 误点一下不会把你直接丢进一个 1428 张的库里。

> **重命名只改过片里显示的名字，磁盘上的文件夹不会改名。**
> 目录路径是 catalog 的键，改名会让所有缩略图缓存和已做的决定失联。

1. 点**打开文件夹**，选一个装满照片的目录
2. 等它分析完（93 张 24 MP 大约 6–8 秒）
3. 开始过片

### 快捷键

| 键 | 作用 |
|---|---|
| <kbd>→</kbd> / <kbd>K</kbd> | **过** —— 这张过。按住先预览，松手才生效 |
| <kbd>←</kbd> / <kbd>J</kbd> | **不过** —— 这张我不过。按住先预览，松手才生效 |
| <kbd>空格</kbd> | **精选** —— 过，而且这是里面最好的。再按一次取消，原地不前进 |
| <kbd>↓</kbd> / <kbd>↑</kbd> | 下一张 / 上一张（只是翻看，不改任何状态） |
| <kbd>Backspace</kbd> / <kbd>Ctrl+Z</kbd> | 撤销上一次决定 |
| <kbd>Z</kbd>（按住） | 临时放大到 100% 看是否对焦 |
| <kbd>I</kbd> | 显示 / 隐藏人脸框 |
| <kbd>P</kbd> | 过曝斑马纹 |
| <kbd>G</kbd> | 网格视图 |
| <kbd>C</kbd> | 跳到相似组内下一张 |
| <kbd>L</kbd> | 显示 / 隐藏左侧列表 |
| <kbd>F</kbd> | 全屏 |
| <kbd>0</kbd> | 恢复适应窗口 |
| <kbd>?</kbd> | 快捷键帮助 |

滚动缩放，拖动平移，双击在「适应窗口」和「100%」之间切换。
**未放大时左右拖动 = 拖卡片**，拖回中间即取消。

### 设置

首页左栏底部的齿轮，或者直接打开 <http://127.0.0.1:8765/#settings>。

| 行为 | 判定 | 高级 |
|---|---|---|
| 隔离文件夹名 | 判定严格程度（宽松/标准/严格） | 分析进程数 |
| 移动前再确认一次 | 连拍分组窗口 | |
| 以只读方式打开库 | 分析分辨率 | |
| 打开库时显示 / 默认排序 | | |
| 界面密度 | | |

三条规矩：

- **三档，不是数字。** EYE_BLINK_MAYBE = 0.40 不是人能在脑子里想象的东西，
  所以它永远不出现在界面上 —— 界面上是「宽松 / 标准 / 严格」，由服务端决定那意味着什么。
- **每一个开关都真的接到了东西上。** 加一项的前提是它能改变行为；
  一个存了值却没人读的开关，比没有这个开关更糟。
- **严格程度会重新缩放基准值**，所以连点两次「严格」不会累积 —— 每次都是从出厂值重新算。

![设置](docs/img/settings.png)

## 你的照片是安全的

这个软件在设计上不允许自己伤害你的文件：

- **筛选全程不碰原图。** 「不过」只是数据库里的一个字段。
- **决策和执行分开。** 你决定的是一张照片的判断，不是一次文件操作。
- **执行要二次确认**，而且只是**移动到隔离文件夹**，不是删除。
- **每次执行都有日志，一键回滚。**
- **`--read-only` 可以全程只读**，连隔离文件夹都不建。
- **不联网。** 没有云端接口、没有用量计费、没有遥测。照片一个字节都不出这台机器。

## 常见问题

**支持 RAW 吗？**
支持。ARW / CR3 / NEF 等会转码一次用于预览和分析，原文件不动。
浏览器原生支持的格式（JPEG / PNG / WebP）在放大时**直接给你原文件**，不重新编码 ——
本地优先，没有带宽要省，而 1600px 的预览放大到 400% 就是一张糊照片。

**会修改我的 EXIF 吗？**
不会。除非你显式选择 XMP 模式，那时才会写入评级。

**分析一张要多久？**
93 张 24 MP JPEG 大约 6–8 秒（多进程）。1428 张大约 2 分钟。

**为什么「眼睛可能闭着」以前会误报？**
修好了。原因是它拿**单只眼睛**的证据下结论 —— 模型的 `eyeBlink` 输出带系统性的
单侧偏差，实测四张照片都是"一只眼 0.45、另一只 0.25"，四张全被判成眨眼，**没有一张是真的**。
现在要求**双眼同时**过阈值（真眨眼本来就是双眼闭合），那四张误报全部消失；
`CATCHLIGHT_MIN` 也从分布中位数上挪开了。细节写在 [docs/design.md](docs/design.md)。

**能用网页版吗？**
不能。浏览器里只有 Chromium 系的 `File System Access API` 能读写本地目录，
Firefox 和 Safari 都明确不支持，等于放弃三成用户；而且浏览器没有多进程，
分析会慢 3–5 倍，RAW 也无法解码。桌面程序是对的选择。

## 从源码运行

需要 **Python 3.10+**。

```bash
git clone https://github.com/N0ts/guopian.git
cd guopian
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
python run.py --dev          # 开发模式：改 web/ 自动刷新，改 guopian/ 自动重启
python run.py                # 普通模式
```

**没有人脸模型也能跑核心功能** —— 缺失时会在界面上明确提示，而不是静默降级。

### 自己打包

```bash
python scripts/build.py
```

输出在 `release/`。用 PyInstaller 打成 onedir，两个 EXE 共用一个 `COLLECT`，
所以不会重复打包一遍依赖。

### 提交前跑一遍

```bash
python evaluation/hygiene.py        # 封装守卫：文案单一来源、颜色只在 :root、无外链
python evaluation/api_test.py       # 接口
python evaluation/anim_check.py     # 动画时长与 JS 等待是否一致
python evaluation/zoom_sharpness.py # 放大后是否真的是原图
node   evaluation/web_smoke.js      # 前端冒烟（含拖拽物理）
```

> `hygiene.py` 守着两条**这个项目已经破过一次**的规矩：决策用词只能写在
> `config.py` 一处、颜色只能写在 `:root` 里。两条都是破坏了也不报错的类型 ——
> 只会让界面上的词对不上，或者让换配色变成一场搜索。**不被检查的规矩一定会漂移。**

> 注意：`web_smoke.js` 的 DOM 是合成的空壳，**不解析 `innerHTML`**。
> 任何依赖渲染结果的断言在那边都是假测试 —— 不要写。

## 技术选择

| | 用了什么 | 为什么 |
|---|---|---|
| **前端** | 原生 JS + CSS，**零依赖、无构建步骤** | 一个本地工具不需要 Webpack。打开 DevTools 看到的就是源码 || **后端** | Python 3.10 + Flask，只监听 `127.0.0.1` | 生态里图像处理和人脸模型最成熟的地方 |
| **人脸** | MediaPipe Face Landmarker（Tasks API） | 一次推理拿到 478 关键点 + 52 blendshape + 头部姿态，全本机 |
| **图像** | Pillow + numpy | 够了，而且不会引入一个几百 MB 的依赖 |
| **存储** | SQLite（WAL） | 单文件、零配置、可只读打开 |
| **打包** | PyInstaller onedir | 双 EXE 共用 COLLECT，避免重复打依赖 |

界面是深色的，这不是风格选择 —— **看照片时周围越暗越好**。
主色是中性近黑 `#0B0C0E`，不是生成器爱给的蓝调深色：有色的环境光会改变你对照片的判断。

### 前端是浏览器原生 ES module（十一个文件，零依赖、零构建）

```
web/index.html          唯一的 <script type="module" src="/home.js">
web/core.js      72 行  G（$ $$ api toast esc sleep fmtCount）+ 视图切换   无依赖
web/state.js     70 行  el / S / V / LABEL / VERDICT / OWNED / cur        无依赖
web/view.js     186 行  适应窗口、缩放、平移、滚轮与双击手势
web/physics.js  376 行  拖拽刚体积分器 + 鼠标手势 + 蒙版/印章反馈
web/histogram.js106 行  人脸框、直方图、过曝斑马纹
web/list.js     192 行  左侧照片列表 + "上次看到哪一张"的记忆
web/card.js     313 行  卡片本身：预览、原图、建议、问题标签、元信息
web/grid.js      91 行  网格视图（框选批量决定）
web/keys.js     159 行  键盘。全应用唯一一处键位表
web/app.js      609 行  接线层：生命周期、决策流程、对话框、以及所有模块的装配
web/home.js     485 行  首页：项目列表、详情、文件夹浏览器 —— 也是唯一入口
```

依赖只有一个方向，没有环：

```
core.js  state.js                      ← 叶子，谁都不 import
   ↑         ↑
 view.js ────┤
   ↑         │
physics.js   ├── histogram.js
   ↑         │
 list.js ────┘
   ↑
 card.js
   ↑
 grid.js
   ↑
 keys.js
   ↑
 app.js     ← 所有 configure() 装配都集中在这里
   ↑
 home.js    ← 入口
```

几条向上的线（列表点击要换卡片、物理甩完要落决定、键盘敲了要分发到动作、
库被关掉要回首页）不能 import 回去 —— 那就成环了。它们全部由 `app.js`
在末尾用 `configure({...})` 注入，注入的名字和接收方模块里的占位符同名，
所以被注入的函数体一个字都不用改。

`home.js` 静态 import `app.js`，这一条 import 就是**启动竞态的修法**：
原来是三个普通 `<script>`，`home.js` 末尾直接 `Home.boot()`，它
`await fetch('/api/home')` 之后调 `App.setLabels()` —— 那时 `app.js` 往往
刚解析到一半，能跑只是因为**网络往返比解析 73 KB 慢**。现在求值顺序由
import 图保证，`app.js` 不可能没跑完。

`hygiene.py` 的第 4 组会静态检查：每个 `import` 的路径存在、名字真的有对应
`export`、依赖图无环、每个 `.js` 都是模块（没人往 `window` 上挂东西）、
以及"跨模块用到的名字都 import 了"。

### 组件只有一个基类

所有按钮都是 `.btn` 加修饰符，几何形状写在基类里，修饰符只改颜色和尺寸：

```html
<button class="btn">默认</button>
<button class="btn ghost">次要</button>
<button class="btn primary">主要动作</button>
<button class="btn danger">破坏性动作</button>
<button class="btn primary block lg">整行的大按钮</button>
```

> 这里踩过一次：给主页加按钮时**又写了一个 `.btn`**（`34px` / `.pri` / `.danger`），
> 而项目里本来就有 `.btn`（`30px` / `.primary` / `.ghost`）。同一个概念两个名字，
> CSS 又不报错，后定义的静默生效。`hygiene.py` 现在会数 `.btn{` 出现的次数。
