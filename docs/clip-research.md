研究：本地 CLIP 能不能用来分组、搜场景、判表情

不是接进产品的代码，是为了回答三个问题而做的测量，留在仓库里当证据：
换算法之前先量一遍，比换完再说“应该更准”可靠。

结论（都在这台机器、这个 1428 张的库上实测）：

1. 相似分组 —— 有用，而且正好解决“一张有人、一张没人”那对。
   余弦：真近似重复 0.98，同一场景不同瞬间 0.90-0.95，
   争议那对（双人合影 vs 空景）只有 0.58，真·空景重拍 0.992。
   用“完全连接 + 余弦阈值 0.85 + 15 秒窗口 + 每组最多 12 张”重做：
   371 组、93% 的照片进组、最大组 12 张（现在是单链聚合，最大组 128 张）。
   速度：CPU 上 28 ms/张，1428 张 110 秒。

2. 语义搜索 —— 可用。
   78 个中英双语标签（scene_tags.py），中文词经别名表映射到英文提示词，
   实测「湖」10/10 是湖、「人像」10/10 是人、「雪山」10/10 是雪景；
   docs/img/_clip_湖泊.png 等是这个脚本 `sheet` 子命令生成的对照图。
   检索运行时根本不需要文本编码器：标签向量一次算好存下来，
   每张照片只需一个 512 维向量（float16 存是 1 KB/张）。

3. 表情 —— CLIP 不行，别在它身上花钱。
   整图：与 blendshape 的 Spearman 相关全在 ±0.25 以内，
   “闭眼”提示词的 Top12 里没有一张是闭着眼的（_expr_blink.png，
   它匹配的是墨镜和抬手）。
   换成人脸裁切：只有“笑”这一项起来了（ρ=0.33），
   闭眼 −0.12（方向都反了）、张嘴/眯眼/尴尬 ≈0。
   原因很直白：CLIP 是 224px 的整图语义模型，学的是“这张图讲什么”，
   不是“脸部肌肉怎么动”。表情该用 MediaPipe 已经给出的 52 个 blendshape。

跑法（需要 models/ViT-B-32.pt，不在仓库里）：

    python evaluation/clip_index.py build          # 标签 + 全部照片向量
    python evaluation/clip_index.py sim            # 分组阈值评估
    python evaluation/clip_group_eval.py           # 完全连接 + 分组大小
    python evaluation/clip_index.py sheet 湖 人像   # 生成检索对照图
    python evaluation/clip_expression_eval.py      # 整图表情
    python evaluation/clip_face_eval.py            # 人脸裁切表情

依赖说明：HF 在这台机器上连不通（huggingface.co / cdn-lfs 超时），
权重是从 OpenAI 的 CDN（openaipublic.azureedge.net）下的；
onnxruntime 也没装成，所以现在走的是已经装好的 torch。
真要发版应该导出成 ONNX 只留视觉编码器（量化后约 88 MB），运行时不需要 torch。

（上面这段是当时的处境。后来 onnxruntime 装了 1.22.0 —— 1.31 已经不支持
Python 3.10 —— 模型也导出成 ONNX 量化到 92 MB 了，见 export_clip_onnx.py。）

## 表情：还能做什么（量过，不是猜）

CLIP 那条路已经证伪：整图相关全在 ±0.25 内，「闭眼」提示词的 Top12 里没有
一张闭眼的；改成人脸裁切后只有「笑」起来了（ρ=0.33）。原因很直白：CLIP 是
224px 的整图语义模型，学的是"这张图讲什么"，不是"脸部肌肉怎么动"。

那 blendshape 呢？现在的代码只用了 blink（双眼中位数）+ jaw_open + brow_down
+ gaze + smile，`squint` 算了存了却一次没用（`config.SQUINT_GOOD` 是死常量）。
我按"补三条规则"量了一遍（expression_coverage.py）：

    人脸/眼睛够大可判的        969
    现在被标出的                25（2.6%）
    半眨眼 0.25-0.60            37
    眯眼且没在笑               344   <- 不能用
    左右眼差 ≥0.35             13
    半眨眼 + 不对称合计         50  -> 覆盖 7.7%

「眯眼」直接否掉：344 张（35%）命中，逐张看过全是阴天/雪地里的正常表情。
eyeSquint 在明亮环境里本来就高，把它当缺陷会淹没真正的问题。

「半眨眼」和「左右眼不对称」留着有价值：37 + 13 张，是"值得看一眼"的量级，
不是"每张都报警"。但它们的**上限也就这样**：25 → 75 张，仍只覆盖 7.7%。

真正的结论：**"表情不好"不是靠再加一条阈值能解决的**。要解决的是用法，不是
检测器 —— 一整个连拍里哪一张最好，这个问题现有信号（眼睛、视线、笑、脸部
清晰度、组内相对排名）已经能答；"这张表情不好"这个绝对判断，现有信号答不了。

## 更正：专用表情模型能，而且很轻（已实测）

上面那句原来写的是"加模型也答不了"，这是错的 —— 我那次只试了 CLIP。
换成一个**专门做人脸表情的模型**之后结论反过来了。

模型：`mbf_va_mtl`（MobileFaceNet 多任务，AffectNet 训练），
**8.3 MB、输入 112×112、CPU 上 3.1 ms/张**，输出 8 类情绪 + 效价/唤醒。
模型和标签顺序来自 [HSE-asavchenko/face-emotion-recognition](https://github.com/HSE-asavchenko/face-emotion-recognition)。

在你这 969 张近景脸上的结果（fer_probe.py）：

    中性 81%   开心 6.3%   轻蔑 7.4%   惊讶 4.5%   其余 <1%
    "开心"概率 与 MediaPipe smile blendshape 的相关 r = 0.51
    效价（valence）-0.51 .. 0.83，均值 0.13

对照图看了：「开心」Top32 全是真在笑的（含几张墨镜后的大笑）；
「效价最低」的 16 张是严肃、走神、半闭眼那种 —— 正是"表情不好"的候选。
同一批裁切上传给 CLIP，它能给出的最好成绩是 ρ=0.25（只能看到"在笑"）。

**但这一路上我自己踩了两个坑，值得记下来，因为它们决定"能用"还是"垃圾"：**

1. `faces` 表里的 `(x, y, w, h)` 是**左上角 + 尺寸**，不是中心点。我第一版当中心
   点用，每张脸往左上偏了半个框，于是"开心"的 Top32 全是**戴墨镜的人**
   （墨镜刚好落在偏移后的框里）。现在裁切收口到 `evaluation/facecrop.py`。
2. 标签顺序不能猜。AffectNet 8 类的下标是
   `0 生气 1 轻蔑 2 厌恶 3 害怕 4 开心 5 中性 6 难过 7 惊讶` —— 我按直觉猜了一遍，
   结果 84% 的照片被判成"厌恶"（其实那一位是**中性**）。

两个坑都修好以后，`开心` 与 smile 的相关从 0.074 升到 **0.51**。同一个模型、
同一批照片，差别只在十行代码。

顺带把 CLIP 那条结论在**修正后的裁切**上重跑了一遍：仍然只有"笑"有信号
（ρ=0.25），闭眼 −0.02、尴尬 −0.07、说话 −0.07。所以"CLIP 判不了表情"这句
站得住，是"CLIP 不行"，不是"模型不行"。

### 该怎么用（比模型本身更重要）

AffectNet 8 类的公开准确率是 **61%–63%**（这个模型的 16 MB 版本能到 61.9%）。
61% 意味着"绝对判断"不可信 —— 拿它给单张照片打"表情不好"会错得很难看。

但**组内相对排序**就稳得多：同一个连拍里同一个人、同一束光，模型不需要判断
"这张好不好"，只需要判断"这八张里哪张更好"，误差会互相抵消。这正好也是过片
已经在做的事（组内排名已经算了眼睛、视线、笑、脸部清晰度）。

所以这条路的正确形态是：**表情分参与组内排名**，而不是"给每张标一个难看"。

### 已经接进过片了（2026-10 第二轮）

- 模型放在 `models/emotion.onnx`（7.9 MB，gitignored），缺就跳过，不影响看照片。
- 单独一遍 `emotion_pending()`，只读预览图：**969 张有脸的照片、24 秒**，一张脸 3 ms。
- 结果存两处：`faces.valence / arousal / emo`（JSON 八类概率），以及
  `photos.face_valence / face_happy`（取组内最正面那张脸，不是平均 ——
  合影里只要有一个人对镜头笑，这张照片的表情价值就成立）。
- 排名权重 `emotion: 0.12`（和"眼睛"同量级），组内 ≥3 张时把效价换成**组内排名**
  再参与加权 —— 绝对效价不可信，相对比较才稳。
- 组里有的照片没脸时不"免考"：缺的贴组内均值。否则没脸的那张因为少一项
  而被抬高，实测有一组的"最佳"因此跳到一张空景上。
- 界面：底部信息行在连拍里标「本组表情最好」；有人的笑时标「笑」。
  闭眼的那几张不参与"表情最好"的评选（实测有张闭眼照片效价最高，因为闭眼
  瞬间常常正是在笑）。

**效果**：368 个多张组里，**120 组（33%）的"组内最佳"换了人**，换掉之后
效价平均 **+0.26**（最差 +0.02，最好 +0.78）。也就是说，这套东西真正改变的是
"这八张里挑哪张"，而不是"这张打几分"。
